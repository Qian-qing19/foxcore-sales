# Foxcore 销售跟踪系统 · 需求基线（实现版）

> 本文件是 48 页课程设计文档的“施工版摘要”，供编码与验收使用。
> 与设计文档冲突时，以本文件为准；本文件未覆盖的，回查设计文档。

## 1. 背景与目标

Foxcore Retail 由两位合伙人在音乐节、展销会设临时摊位卖新奇商品，现有约 17 名销售顾问、28 种产品。现状是“纸质销售单 + 当日 Excel 转录”，导致：漏记、转录出错、佣金核算慢、多维分析滞后。

系统要改善的组织指标（不是功能清单）：

| 指标 | 目标 |
| --- | --- |
| 销售漏记率 | < 0.5% |
| 电子销售记录占比 | ≥ 99.5% |
| 佣金计算错误率 | 0 |
| 佣金核算耗时 | 活动结束后小时级 → 分钟级 |
| 多维查询 | 当天/次日 → 秒级 |

范围：销售登记、佣金核算、销售报表、基础数据维护、历史数据导入。**不含**财务付款、银行结算、仓储物流、供应商采购执行。

## 2. 角色与权限

| 角色 | 账号 | 能做什么 |
| --- | --- | --- |
| 合伙人 | `admin` | 全部：工作台、核算、报表、规则、基础数据、导入、作废 |
| 销售顾问 | `sales01` | 登记销售、查看自己的流水与业绩 |

- 登录：用户名 + 密码（`werkzeug.security` 哈希），session 保存 `user_id/role/salesperson_id`。
- 未登录访问任何页面 → 跳 `/login`；越权 → 403 页面。

## 4. 核心流程

### 4.1 登记销售（UC-01）

1. 销售顾问登录，系统带出其**当前进行中的班次**及摊位。
2. 选择产品、数量、最终单价；可加多行；前端实时合计。
3. 提交时校验：
   - 班次属于本人且状态 `进行中`；
   - 产品 `在售`；
   - 数量为正整数；
   - 单价 ≥ `PRODUCT.min_price_cents`（低于则拒绝整单，提示“需合伙人批准”）；
   - `client_txn_id` 未重复（重复则返回原单）。
4. 写 `SALE`（状态 `已登记`）+ `SALE_ITEM`（多行）。
5. 逐行匹配佣金规则：
   - 命中 → 写 `COMMISSION_ENTRY`（状态 `待结算`），`SALE.status='已计佣'`；
   - 未命中 → `SALE.status='待计佣'`，不写佣金。
6. 返回销售单号。

扩展路径（必须实现）：
- 产品停用 → 拒绝；
- 数量非正整数 → 拒绝；
- 低于最低售价 → 拒绝，提示需批准；
- 一单多商品 → 支持；
- 重复提交 → 幂等返回原单；
- 缺规则 → 保存并标 `待计佣`。

### 4.2 核算佣金（UC-02）

1. 合伙人选择期间（起止日期）、可选活动/顾问范围，点“生成核算”。
2. 系统取该期间内**未作废**销售的 `COMMISSION_ENTRY`（`status='待结算'`）。
3. 按顾问汇总：净销售额、佣金合计、待处理金额（缺规则销售的金额）。
4. 异常清单：缺规则、金额异常、需人工复核的明细。
5. 生成 `COMMISSION_SETTLEMENT`（`草稿`）+ 按顾问的 `COMMISSION_SETTLEMENT_LINE`；回填 `COMMISSION_ENTRY.settlement_id`。
6. 合伙人确认 → 状态 `已确认`，`COMMISSION_ENTRY.status='已结算'`，金额冻结。
7. 确认后修改规则、重算，**不得**改变已确认金额；退款走下一期冲减（P1）。

### 4.3 生成报表（UC-03）

- 维度：产品 / 活动 / 摊位 / 销售顾问（可单选，也可“维度组合”下钻）。
- 时间范围：默认本月，可选活动季。
- 指标：销售数量、净销售额、平均成交价、佣金合计、数据截至时间。
- 口径：排除 `作废`；金额按分汇总后转元。
- 导出：CSV（UTF-8 BOM，Excel 直接打开不乱码），文件名含查询条件与时间。

### 4.4 管理佣金规则（UC-04）

- 规则字段：规则代码、版本号、维度、计算方式、费率或固定额、优先级、生效期、状态、创建人。
- 新增 = 新版本（`version_no` 在同 `rule_code` 下自增），历史版本保留。
- 状态只能 `草稿 → 有效 → 停用`，停用不删。
- 同一销售核算时只命中一条规则；命中多条时优先级高者胜，同级取版本号大者。

## 5. 数据模型（16 张表）

> 金额字段一律 `INTEGER`，单位“分”，命名 `*_cents`。时间 `TEXT`（`YYYY-MM-DD HH:MM:SS`）。

### 5.1 主数据

| 表 | 字段 |
| --- | --- |
| `VENUE` | venue_id PK, venue_code UNIQUE, name, address, description, created_at |
| `EVENT` | event_id PK, venue_id FK, event_code UNIQUE, event_name, event_type, start_date, end_date, description |
| `BOOTH` | booth_id PK, event_id FK, booth_code, location, status（在用/停用）, UNIQUE(event_id, booth_code) |
| `SALESPERSON` | salesperson_id PK, emp_code UNIQUE, name, phone, status（在职/停用）, hired_at |
| `SHIFT` | shift_id PK, salesperson_id FK, booth_id FK, start_time, end_time, status（未开始/进行中/已结束/已结算） |
| `PRODUCT` | product_id PK, product_code UNIQUE, name, category, min_price_cents, status（在售/停用）, created_at |

### 5.2 交易

| 表 | 字段 |
| --- | --- |
| `IMPORT_BATCH` | import_batch_id PK, file_name, imported_by FK, imported_at, row_count, success_count, error_count, status（成功/部分成功/失败）, note |
| `SALE` | sale_id PK, shift_id FK, import_batch_id FK NULL, sale_time, client_txn_id UNIQUE, total_cents, status（已登记/待计佣/已计佣/作废）, void_reason, void_by, void_at |
| `SALE_ITEM` | sale_id FK, line_no, product_id FK, quantity, final_unit_price_cents, line_cents, PK(sale_id, line_no) |

### 5.3 佣金规则

| 表 | 字段 |
| --- | --- |
| `COMMISSION_RULE` | rule_id PK, rule_code, version_no, dimension（PRODUCT/EVENT_TYPE/SALESPERSON/GLOBAL）, event_type_value NULL, calc_method（按比例/按件固定额）, rate REAL NULL, fixed_per_unit_cents INTEGER NULL, priority, effective_from, effective_to NULL, status（草稿/有效/停用）, created_by FK, created_at, UNIQUE(rule_code, version_no) |
| `PRODUCT_COMMISSION_RULE` | product_id FK, rule_id FK, PK(product_id, rule_id) |
| `SALESPERSON_COMMISSION_RULE` | salesperson_id FK, rule_id FK, PK(salesperson_id, rule_id) |

### 5.4 结算

| 表 | 字段 |
| --- | --- |
| `COMMISSION_ENTRY` | entry_id PK, sale_id FK, line_no, rule_id FK, settlement_id FK NULL, base_cents, commission_cents, status（待结算/已结算/已冲减）, created_at, UNIQUE(sale_id, line_no) |
| `COMMISSION_SETTLEMENT` | settlement_id PK, settlement_no UNIQUE, period_start, period_end, scope_desc, status（草稿/已确认）, confirmed_by FK, confirmed_at, created_at |
| `COMMISSION_SETTLEMENT_LINE` | settlement_id FK, salesperson_id FK, net_sales_cents, commission_total_cents, pending_cents, adjustment_cents, PK(settlement_id, salesperson_id) |

### 5.5 登录（实现补充，不改变领域模型）

| 表 | 字段 |
| --- | --- |
| `APP_USER` | user_id PK, username UNIQUE, password_hash, role（合伙人/销售顾问）, salesperson_id FK NULL, status（启用/停用）, created_at |

### 5.6 索引

- `SALE(sale_time)`、`SALE(client_txn_id)` UNIQUE
- `SALE_ITEM(product_id, sale_id, line_no)`
- `COMMISSION_ENTRY(settlement_id, status)`
- `COMMISSION_RULE(rule_code, version_no)` UNIQUE
- `SHIFT(salesperson_id, start_time)`

## 6. 规则匹配算法（伪代码）

```
候选 = 所有 status='有效' 的规则
       且 effective_from <= 销售日期
       且 (effective_to IS NULL OR effective_to >= 销售日期)
       且 (
            dimension='GLOBAL'
        或 dimension='PRODUCT'     且 EXISTS(PRODUCT_COMMISSION_RULE 关联该产品)
        或 dimension='SALESPERSON' 且 EXISTS(SALESPERSON_COMMISSION_RULE 关联该顾问)
        或 dimension='EVENT_TYPE'  且 event_type_value = 活动类型
       )
排序：priority DESC, version_no DESC, effective_from DESC
取第一条 → rule_id
佣金：
  按比例     commission_cents = ROUND_HALF_UP(base_cents * rate)
  按件固定额 commission_cents = fixed_per_unit_cents * quantity
base_cents = line_cents（成交金额）
```

## 7. 状态机

```
SALE:        已登记 ──有规则──> 已计佣
                  └──无规则──> 待计佣 ──补规则重算──> 已计佣
             任意 ──作废──> 作废（不可逆）

ENTRY:       待结算 ──结算确认──> 已结算
             已结算 ──退款冲减──> 已冲减（P1）

SETTLEMENT:  草稿 ──确认──> 已确认（不可改）

RULE:        草稿 ──> 有效 ──> 停用（不删除）
```

## 10. 与设计文档的差异（答辩要主动说明）

1. **登录表**：文档没有 `APP_USER`，实现补充一张，领域模型不变。
2. **金额存分**：文档写 `DECIMAL(12,2)`；SQLite 无精确小数，改存整数分，展示时转元。
3. **状态**：文档图 10 有三套状态（审批/登记/计佣），实现合并为 `SALE.status` 四态，降低复杂度。
4. **导入**：文档为 Excel，MVP 改 CSV（Excel 可另存为 CSV），保留 `IMPORT_BATCH` 与错误行报告。
5. **离线**：不做多终端离线同步；系统本地部署，本身离线可用。
6. **审批**：低于最低售价只做“拒绝 + 提示”，不做合伙人审批工单。
